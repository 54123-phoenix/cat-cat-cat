# B4：参考库管理可见性验收

日期：2026-10-31。**B4 本地验收通过；ISS-028 按管理员触发重建的生命周期范围关闭。** B1—B4 的控制流与管理反馈已接通，真实识别效果、Docker、实际 Redis、容量与远端 CI 仍分别待验收。本轮未提交、推送、部署或修改真实业务数据库；迁移 head 仍为 i20261031。

## 问题与实现

此前管理员只能通过 API/CLI 查询构建，页面无法区分“档案保存”“资料待发布”“参考版本可用”，也没有任务进度和失败重试入口。

管理台新增“识别参考库”栏目：展示档案/登记参考图数量、尚无照片的猫、最近发布版本及时间、待发布变化、当前兼容性、最近 20 个任务及图片处理进度。管理员可以重建并发布或重试失败/中断任务，审核员只读。候选发布、主动选择旧版本回滚仍使用 CLI/API，重试保留原任务操作及裁剪/是否发布选项。

GET /api/admin/reference/status 增加明确 Pydantic 响应模型，保留旧字段，补充 current_catalog、published、pending_changes、jobs、checked_at 与分区错误。目录/版本信息独立于模型校验，所以模型缺失不会让管理员丢失档案和任务信息。资料无法核对时 pending_changes 为 null，不冒充“没有变化”；历史任务成功与当前可用性分别展示。源图缺失的诊断补充图片 ID 和路径。

新 Web 模块从 unknown JSON 校验字段、枚举、ID、时间和进度后渲染，没有新增 any 断言。复用管理认证传输，补齐嵌套错误码与外部取消信号。页面每 5 秒刷新，隐藏页面/离开栏目后停止后台轮询；提交期间阻止重复点击并取消旧状态请求。提交响应丢失时重新查询任务，不自动重复 POST；状态请求失败时保留旧数据、标记待确认并暂停操作。任务完成后移除“等待结果”提示，100% 图片进度也不会提前显示发布成功。

猫档案保存后明确引导核对参考库。新增档案成功但照片上传失败时，保留已创建 ID 与待上传照片，重试复用该档案，避免重复创建。管理栏目支持横向滚动，提示使用可读颜色；参考库模块支持键盘、语义进度、明暗主题和减少动画。

## 验收过程中的限制与异常

- 既有浏览器第一次并发回归在图鉴导航时发生开发服务 ERR_CONNECTION_REFUSED，没有完成剩余流程。保留 `artifacts/optimization-b4-core-browser` 的失败记录；单独复跑全部六组通过。没有证据确定该次服务中断的根因，不把失败运行登记为通过。CI 顺序运行两份浏览器脚本，本地也建议顺序运行。
- 后端 66 条 warning 是现有 Pydantic/httpx 弃用提示，新增 4 个 API 夹具多触发 4 条 httpx 提示。Web 测试含已有工具链弃用提示及错误边界故意抛出的 Error: test，最终断言均通过；没有关闭规则掩盖错误。
- 主 JS 约 503.33 kB，保留超过 500 kB 的构建提醒；未做容量或加载性能验收。状态轮询仍会完整校验文件哈希，数据量增大后需测量 I/O 成本。
- 当前“可用”只代表参考资料兼容，不是识别模型质量保证；无参考照片的猫不进入匹配候选。真实模型、数据库容器、实际 Redis 故障、微信、地图与 LLM 的 VER 项不随 ISS-028 关闭。
- 保留 B2/B3 的单机本地文件系统约束、人工清理与备份边界；本轮不新增自动任务重试、任务取消或自动触发推理。
