# B1：参考身份与版本校验验收

日期：2026-10-30。状态：**B1 本地控制流验收通过；ISS-028 部分完成，未关闭。** 本轮未提交、推送或部署，未迁移真实业务库，也未下载/运行真实模型权重。此前 A 阶段与初始修复证据保持原样。

## 问题与实现

旧识别加载器永远缓存数字 ID 和名字；独立 NPZ 或按名字重绑的 JSON 没有数据库、模型、图片的共同来源依据，读取成功不代表猫身份正确。

本轮增加 `h20261030` 迁移，给数据库及猫分配持久身份，保留数字 API ID；数据库触发器阻止已建立的身份被更新。新增严格快照清单与源图/模型/产物 SHA256 校验，目录修订使用当前数据和源图内容的规范化摘要。改名保持身份与向量可用，读取时使用最新名字；增删猫或参考图、覆盖源图会使旧快照失效。

运行时只使用已校验的向量，FAISS 和 NumPy 共用映射；移除独立旧索引和按名字猜测绑定，不再在用户识别请求内写索引。推理前后验证版本，错误明确返回 unavailable。模型缓存绑定实际加载字节哈希，检测器也检查本地权重哈希；移除首个请求时的自动下载。

新增只读、非发布的 `build_reference_snapshot.py`：从已经登记的 CatImage 构建新的候选目录；不修改猫档案，不覆盖已有目录，不跳过失败照片。旧 `build_reference_db.py` 明确拒绝运行，避免继续提供 reset 和无来源的产物；历史名称导入工具仍仅导入元数据，改为要求已迁移数据库并明确提示未建立识别参考。

新增受管理员/审核员权限保护的 `/api/admin/reference/status` 诊断接口。系统健康不再仅凭旧 JSON 维度一致判定参考资产有效。操作说明、配置与首次隔离环境用法见 [REFERENCE_LIBRARY](../REFERENCE_LIBRARY.md)。

## 限制与下一包

- 本轮验证的是身份、完整性和错误控制流，不能据此报告真实 Top-1/Top-3、误接受率、无猫识别效果或线上延迟。真实模型及数据许可继续由 VER-001/007 验收。
- 清单哈希不等于发布者签名；它用于校验已确认来源的本地产物一致性。旧向量不能通过手工填写清单获得来源证明。
- 当前候选构建不负责异步任务、单写入者协调、原子当前版本指针、自动 worker 刷新或回滚。B2/B3 继续完成这些内容及两个真实进程的故障验收；管理页面的参考库状态展示属于 B4。
- 为保证失效正确性，本轮每次识别完整校验源图、模型和向量，并重建内存索引，I/O 和内存成本尚未优化。B3 的缓存改造必须保留相同拒绝语义，之后再做性能测量。
- 迁移链目前只验收 SQLite。应用配置切换 REFERENCE_DIR 并重启只用于首次隔离验证，不冒充多进程原子发布方案。
