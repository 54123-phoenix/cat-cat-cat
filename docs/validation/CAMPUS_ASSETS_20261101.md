Git 历史 `4c0b21d:scripts/download_assets.py` 指向公开备份 [echophoenix/cat-cat-data](https://huggingface.co/datasets/echophoenix/cat-cat-data/tree/61e619ea06bba63f48d03f470794ae8d24870bcc)。本次将版本固定为 `61e619ea06bba63f48d03f470794ae8d24870bcc`，完整读取目录 API 及分页链接，共 134 个文件：1 个 `.gitattributes`、130 张单独图片、3 个分卷。没有该旧脚本请求的 `cat-cat-uploads.tar.gz`，也没有目录级身份/场次说明文件。

130 张独立图片总计 208,455,690 字节；3 个分卷各 524,288,000 字节，总计 1,572,864,000 字节。全部下载到隔离审查目录并校验发布的 SHA256。一张独立图首次下载出现 TLS EOF，重试后全部 133 个 LFS 文件的大小和哈希通过。分卷损坏结论来自对已通过哈希校验内容的解压，不是这次网络重试失败。

三个分卷按 part001→part003 拼接读取，压缩流在 `uploads/cats/582eec90_56049_1.jpg` 中途结束，抛出：

```text
EOFError: Compressed file ended before the end-of-stream marker was reached
```

此前列出 6,115 个成员，其中 8 个目录、5,166 个 HF 上传缓存 metadata 文件、1 个缓存 gitignore、940 个图片成员；最后一个图片成员不完整。完整普通文件 6,106 个中含 **939 个完整图片文件**。只保留完整图片为候选，最后半张图的 `.partial` 不参与盘点。这 5,166 份缓存记录不是完整原图库清单，也不是猫身份或拍摄元数据；抽查内容为缓存时间、大小、哈希和上传状态。不能从缓存条目数推断总猫数或精确丢失张数。

这验证了 **ISS-043：现有历史备份不完整**。能够读出前缀不等于恢复成功，单个分卷哈希正确也不证明所有分卷齐全。需要取得完整源照片或剩余分卷后重新验证完整压缩流，才能关闭。

## 本轮实现与验证

新增 `cat-backend/scripts/prepare_campus_dataset.py`，只读取图片与准备清单：记录文件和像素哈希、EXIF 原始日期候选；要求身份、实际图库、拍摄场次和来源/使用依据；阻止同场次跨参考/校准/留出、未知猫混入图库、重复内容和未复核近似图。缺信息或格式不对返回 `needs_preparation`；多猫不能强行按单目标身份计分。输出文件不能覆盖已有文件。完整说明见[准备文档](../CAMPUS_DATA_PREPARATION.md)。

工具是独立的资料检查入口，尚未接入模型评测/校准工作流；通过它只表示所填资料满足检查规则，不能证明标签真实、样本量足够或发布通过。校园实验还需要独立冻结协议及图库绑定。

本机生成了原始盘点清单、自动排除 132 份精确副本的待填写清单，以及完整准备检查结果。**937 个候选记录（936 静态图＋1 MPO）仍未分组、未核对身份/场次**；未编造元数据、未给出校园准确率。近似图检查未发现 dHash≤4 候选，这不等于照片独立或没有同场景相关性。

新增 16 项针对性测试全部通过，覆盖三种跨分组场次混用、未知身份在图库、缺少负样本场景、同像素重新编码、近似图审核绑定哈希、EXIF 不自动认证、mtime/导入时间拒绝、路径越界、坏图/LFS、覆盖保护和坏 JSON。全量后端 **303 passed / 68 warnings / 189.04s**，没有新增依赖；原始日志见 [campus-backend-tests.log](campus-backend-tests.log)。这只是工具和工程回归证据。

历史同步 PowerShell 入口不再索取 token 或调用已删除脚本后打印“完成”；直接退出 2 并指向准备文档，实际命令验证通过。此修正不恢复缺失照片，ISS-043 保持未解决。
