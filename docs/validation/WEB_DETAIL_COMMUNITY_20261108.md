# Web 详情、社区与图片优化（2026-11-08）

延续同日首轮 Web 优化，保留橙色校园风格、真实照片、审核规则和既有识别默认策略。本轮在本地修改并使用临时 SQLite、临时上传目录和浏览器隔离验收；没有迁移业务数据库、部署或采集新图片。

## 改动

- 猫咪详情按档案、偶遇、健康、关注分别加载，失败可局部重试，已读取内容可保留。未知状态不显示为零，旧请求也不会覆盖新猫咪资料。关注重试先核对服务器状态，再完成原操作意图，避免响应丢失时重复写入或反向切换。
- 详情优先展示照片、基本资料与记录入口；长名称换行，次要资料可展开。记录偶遇转到现有拍照、识别、核对流程，不再直接创建无照片的记录。时段图说明统计的是已加载的至多 100 条公开偶遇，零次不画非零柱，不暗示未来出现概率。
- 社区发帖以正文、照片为先，话题、类型、关联猫和标签放入选填区。关闭弹窗保留本页草稿；离开页面仍不会保存。校验 JPEG/PNG/WebP、每张 10 MiB、最多 9 张，以及投票选项；发布失败保留输入，进行中防重复操作。
- 发帖、举报、删除及大图使用原生对话框，补齐 Escape、动态焦点循环、关闭后焦点恢复。修正父容器间距影响对话框位置的问题。大图切换和图片重试不会丢失键盘焦点，缺失图片也不会错位显示另一张。
- 帖子列表区分空态、首次加载失败、分页失败和刷新失败；已有帖子可继续浏览并重试。图片格子比例固定，点赞和投票失败有反馈，正文与回复入口可用键盘访问。
- 共用图片组件支持响应式尺寸、异步解码、慢加载提示和原图回退。仅同源 `/uploads/` 请求缩略图，外链、blob 和内联图片保持原地址；缩略图不可用时只回退原图一次。大图使用原图并可手动重试，卡片内部不会嵌套重试按钮。

真实接口联调同时修复了三个旧缺陷：详情偶遇使用错误的 `catId` 参数而混入其他猫记录；有健康记录的档案因未声明列表元素类型而序列化失败；帖子关联猫咪未通过 ORM 关系回显。分别保留行为或接口回归。

## 图片交付与边界

`/uploads/<path>?w=160|320|640|960|1280` 按宽度生成静态 WebP（质量 78），保留比例和透明度，纠正 EXIF 方向，不放大、不改写原图。限制源文件 10 MiB、1600 万像素及边长，输出高度不超过 4096px；不支持或超过限制时前端回原图。原图路径权限、链接和越界检查保持，并覆盖缓存后文件替换、链接改向及根目录替换。

每个进程最多同时处理 2 个图片操作，等待 0.5 秒后以 503 和 `Retry-After` 返回。LRU 上限为 128 项 / 32 MiB，**只计算编码后的缓存体，不是进程内存上限**。解码、方向纠正及颜色转换的副本仍可能占数百 MiB，多 worker 还会叠加资源消耗。缓存及 ETag 的 304 请求仍会读取、哈希源文件，以检查替换；目前优化的是客户端图片流量，服务端容量需要另测。

合成 JPEG 验证：2400×1600、4,504,154 B → 640×427 WebP、83,934 B，字节减少约 **98.14%**，原图哈希与原图接口内容不变。这是固定种子噪声图片的本地验证，**不代表真实校园照片的节省比例、画质或弱网速度**。高峰降级原图时流量也会回升。

浏览器尺寸模拟不代替真机，临时环境也不代替服务器验收。原有校园评测、生产恢复、容量与许可专项保持待验，问题台账数量没有因 UI 修改重算。

验收结束后已停止临时预览和浏览器测试进程，临时数据库与附件由验证工具清理；现有业务资料及此前工作区改动保留。
