# Web 吉祥物接入验收 · 2026-11-09

用户确认 A 的蓝白猫形象与 B 的细腻插画质感融合版后，已完成本地 Web 接入。默认复旦蓝 `#0E419C`、Noto Sans SC 与真实猫照片保持；本轮没有部署服务器。

## 交付内容

- 对已确认原图进行本地 IS-Net 分割和 alpha matting，保留白毛、蓝色额纹、眼睛、耳朵与蓬松尾巴，清理白底边缘。原图与生成记录保留在 `output/imagegen/fudan-blue/hybrid/`。
- 全身图提供 192/384/768px WebP，头像提供 96/192px WebP，另有 PNG 回退、favicon、Apple touch icon 和社交预览图。素材位于 `cat-frontend/public/brand/`，网站不依赖模型或外部图床。
- 导航、登录页与分享标识采用独立头像裁切；首页欢迎区、空状态、已有吉祥物位置和通用路线分享插画采用完整坐姿。真实猫照片缺失时继续使用其原有缺图反馈，避免把吉祥物误认为真实猫档案。
- `BrandImage` 预留尺寸、隐藏重复的装饰图像朗读，并处理 WebP → PNG → 爪印回退。`MascotCat` 保留调用参数，但当前素材只有一种表情，由附近文案说明状态。普通插画保持静态，反馈动画与加载外圈遵守减少动态效果偏好。
- 图库筛选按钮改用主题表面色和主按钮文字色，点击高度 44px，保留筛选逻辑及 `aria-pressed`。
- 修复分享猫卡的透明背景：猫卡与通用分享卡增加随主题变化的实色底，避免导出图片在深色查看器中不可读。猫卡二维码增加白底、四模块留白和 128px 输出，适配深色背景与二倍导出。

常用头像 5,284 字节；全身 192px 为 11,030 字节，384px 为 29,168 字节。PNG 仅作为失败回退，社交预览图不参与页面初次加载。

## 浏览器与视觉验收

使用 `artifacts/web-mascot-20261109/preview.py` 创建一次性 SQLite 数据库和临时上传目录。API 监听 `127.0.0.1:8021`、Web 监听 `127.0.0.1:5191`；登录通过隔离账号完成，不读取或写入业务数据库。

- 首页：320、390、768、1280px，复旦蓝/深色共 8 组；无横向溢出，吉祥物位于欢迎区内，按钮不重叠，常规插画无动画。逐张检查了截图与透明素材的白底、蓝白底、深色底边缘。
- 图库：通过实际“黑”筛选进入空状态，图像正常、操作可见；深色及浅色截图通过。筛选按钮的实测文字对比度分别为 9.31/7.29 和 7.89/9.42，点击高度均为 44px。
- 2× 像素密度：头像加载 96px 版本，全身加载 384px 版本，无图片失败。
- 组件隔离场景：使用 Vite 提供的实际 `EmptyState`、`CatSpinner`、`MascotCat` 模块，验证空状态操作、错误重试、减少动态效果；这些是组件测试场景，不冒充业务接口返回。
- 显式阻断 WebP 后正常回退 PNG；同时阻断 PNG 后显示固定尺寸爪印，无破图。常规流程的品牌资源 HTTP 错误和浏览器未捕获异常均为 0。
- 实际下载：明暗两套路线分享卡及猫卡为 720×1280 PNG，年度报告为 750×1334 PNG。逐像素检查 alpha 范围为 255–255，背景完整不透明；肉眼核对路线卡的新头像与完整形象，以及猫卡导出头像。OpenCV 从明暗两张猫卡中均解码出正确的本地猫档案分享链接。
