## 行为变化

此前 `/uploads/{filepath}` 把路径字符串具有相同前缀当作属于上传目录，导致 `uploads_neighbor` 等相邻目录也能通过；没有解析目录联接/符号链接的真实目标。

现在[上传文件路由](../../cat-backend/app/main.py)先拒绝带锚点的绝对、驱动器或 UNC 资源路径，再用 `Path.resolve()` 解析上传根目录及请求文件，按目录层级关系判断归属。解析后越界返回 403；目录内正常文件返回 200，不存在的文件或目录请求返回 404。只要解析后的目标仍在根目录内，合法的相对路径和内部链接仍可访问。

[新增回归测试](../../cat-backend/tests/test_upload_serving.py)通过 TestClient 访问实际应用路由和中间件，文件内容来自临时目录；没有用假的路径解析函数替代应用实现。文件服务无需数据库和启动任务，因此测试客户端不启动 lifespan。测试进程配置内存数据库、测试密钥和隔离上传目录，不操作真实用户数据。

[安全检查](../../harness/checks/security_check.py)不再搜索旧的 `startswith` 写法，而是用当前 Python 解释器执行这组 HTTP 测试，失败则返回非零退出码。运行该检查现在需要安装后端测试依赖；其余静态检查仍保留，不能把本项通过解释成完整安全审计通过。

复跑专项验收：在已安装 `cat-backend/requirements-dev.txt` 的 Python 环境中，从仓库根目录执行：

```powershell
python harness/checks/security_check.py
```

该命令会为子进程设置测试凭据、内存数据库和临时上传目录，并执行同一组路径回归。完整后端测试使用以下隔离配置，上传目录是临时目录，测试完成后可自行清理：

```powershell
$env:DATABASE_URL = 'sqlite://'
$env:JWT_SECRET = 'test-jwt-secret-key-for-pytest'
$env:ADMIN_PASSWORD = 'testadmin123'
$env:INIT_DEMO_USER = '0'
$env:UPLOAD_DIR = Join-Path ([IO.Path]::GetTempPath()) ('cat-iss001-' + [guid]::NewGuid().ToString('N'))
Push-Location cat-backend
try {
    python -m pytest tests -q --tb=short
} finally {
    Pop-Location
}
```

以上代码块应在单独的测试终端运行，避免把测试环境变量留给正常服务启动。项目已有测试在模块导入时配置数据库，本轮没有重构该测试结构。
