# B2/B3：参考库任务、发布、刷新与回滚验收

日期：2026-10-31。**本地控制流验收通过；ISS-028 保持部分完成，下一包为 B4 管理可见性。** 本轮未提交、推送、部署，也未迁移真实业务数据库。使用临时 SQLite、合成 checkpoint/向量和测试推理适配器，未下载或运行真实模型。

## 问题与实现

此前只有 B1 独立候选构建，没有共同的任务记录、单写入者约束、当前版本指针和多进程切换机制。审核创建档案与识别参考更新仍是不同操作。

新增 i20261031 迁移：SQLite 触发器在猫身份/成员和参考图 ID、归属、路径变化的同一事务内递增 generation，事务回滚也回滚计数；改名与无变化更新不递增。清单升级为 v2，v1 必须重建。内容哈希继续发现未经过 SQL 的源图覆盖。

REFERENCE_STORE 保存数据库绑定、任务日志、staging、不可变版本和 current.json。管理员 API 或 CLI 仅入队，独立 worker 执行全量推理。OS 文件锁覆盖构建/发布，进程退出会释放锁；校验通过后提升候选目录并原子替换 current.json。最后校验及指针交换由 SQLite BEGIN IMMEDIATE 阻止目录并发写入。支持候选构建、发布和受当前兼容性约束的回滚。

读者从指针校验实际加载的清单、数据库/照片/模型和产物；缓存已验证快照及 FAISS/NumPy 索引，短锁替换引用，保留每次完整哈希检查。推理前后检查发布 ID。失败构建保留仍兼容的旧版，目录失效或指针损坏时拒绝旧缓存；不会把不可用误报为 unknown。

持久任务包含输入计数/摘要、模型哈希、图片进度、结果 ID 和失败原因。异常退出后，持锁恢复根据权威指针把遗留 running 判为 interrupted 或 succeeded/recovered。历史发布成功和当前参考库兼容性分别判断。损坏任务日志有明确错误，不静默遗漏；管理状态继续返回参考库诊断与 job_error。

系统健康已读取托管当前版本，避免误查旧 embeddings 路径。Compose 新增独立 reference-worker，与后端共享配置和数据挂载；worker 等待迁移，自己不执行迁移。CI 配置保存多进程验收产物。操作、迁移、备份边界见 [REFERENCE_LIBRARY](../REFERENCE_LIBRARY.md)。

多进程综合场景实际执行：

1. 两个 HTTP 进程读取首次发布，Redis 禁用。
2. 提取失败不替换仍兼容的旧版本。
3. 并发入队/worker 被锁拒绝，终止构建进程后可重试并恢复 interrupted 状态。
4. 构建期间通过独立 SQL 连接替换猫/参考图，阻止陈旧发布，两个读者均返回 unavailable。
5. 重建后两个读者切换到新猫身份，拒绝回滚到旧计数版本。
6. 损坏候选拒绝发布；修复测试产物后，兼容发布与回滚均被两个读者发现。
7. 指针替换后立即 os._exit(77)，新 worker 根据指针恢复成功任务。
8. 当前指针损坏拒绝缓存；恢复测试指针并重启一个 HTTP 进程后重新加载有效版本。

这些故障注入只作用于临时目录；生产目录不允许直接编辑指针、向量或清单。专项中发现 Windows 只读文件句柄不能用于 fsync，提升版本前已改用可写句柄；最终多进程场景再次通过。

## 限制、下一包与回退

- B4 尚未交付：管理页面需要展示当前/待发布状态、进度、失败原因及重试，不能只把“档案已创建”显示为“可以识别”。ISS-028 因此不关闭。
- 未安装/调用真实模型，不报告 Top-1、误接受率、无猫效果或延迟。VER-001 与模型/数据许可独立验收。
- Redis 禁用证明发布机制不依赖通知，不等于真实 Redis 中断/恢复测试；Docker、真实 Redis 和远端 CI 未运行。
- 当前仅支持 SQLite 加单机共享本地文件系统。NFS、多主机、断电/磁盘故障未验收。文件系统和数据库不是跨系统原子事务，恢复以指针为发布依据并重新核对当前输入。
- 全量源图/模型/产物哈希仍有 I/O 成本，构建与服务各自加载模型也有内存成本。没有性能承诺、自动清理、任务取消或自动重试；历史版本和失败 staging 需停 worker 后按保留策略处理。
- 原备份脚本只覆盖数据库与默认 uploads，store 和模型需在同一停写/停构建窗口另行备份。正式升级前演练恢复；若需要回退代码，恢复匹配的数据库、资源和参考库组合。禁止用删除身份/降低计数的 downgrade 或运行中覆盖 current.json 回退。
